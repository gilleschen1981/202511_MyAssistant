# Flutter任务与时间管理App - 需求文档

## 目标平台

### 平台支持策略
- **唯一支持平台**: Android 专属应用
  - 最低支持版本: Android 5.0 (API 21)
  - 推荐版本: Android 6.0+ (API 23+)
  - 目标SDK: 最新稳定Android版本
  - 完整功能支持和优化

### 开发与测试环境
- **开发环境**: Android Studio with Android SDK
- **测试环境**: Android Emulator (AVD)
- **设备测试**: Android物理设备（手机/平板）

### 不支持的平台
- **iOS**: 项目不支持iOS平台
- **Web**: 不作为发布或测试目标
- **Desktop**: 不支持桌面平台（Windows/macOS/Linux）

### 屏幕方向支持
- **唯一支持方向**: 竖屏模式 (Portrait)
  - 应用锁定为竖屏方向
  - 不支持横屏模式
  - 不进行任何横屏适配
  - 设备旋转时保持竖屏显示

## 文档概述

本文档包含Flutter任务与时间管理App的完整需求设计，按照UseCase结构组织，涵盖以下模块：

1. **计划管理** - 目标管理与计划管理
2. **任务执行** - 任务列表、任务更新与执行
3. **结果回顾** - Plan列表与执行历史
4. **配置** - 系统配置管理
5. **用户管理** - 用户认证与账户管理

## 核心概念与实体关系

### 主要实体
- **Goal (目标)**: 长期或中期的目标
- **Plan (计划)**: 为实现目标而制定的具体计划模板
- **Task (任务)**: Plan的具体执行实例

### 实体关系
- Goal → Plan: 1:N关系（一个Goal可以有多个Plan，Plan离开Goal无法单独存在）
- Plan → Task: 1:N关系（一个Plan生成多个Task，Task离开Plan无法单独存在）
- Task状态流转: Active(进行中) → Completed(已完成)/Skipped(已跳过)

### Task核心设计原则
1. **Task自动生成**: 所有Task都由Plan根据规则自动生成，不支持手动创建
2. **Task不可变性**: Task生成后不能修改内容，只能更新执行状态
3. **单一执行原则**: 每个Plan同时只能有一个进行中(Active)的Task
4. **历史永久保存**: Task不会被删除，完成后作为历史记录永久保存

## 1. 计划管理

### 1.1 目标管理

#### 1.1.1 创建目标
- **角色**: 已认证用户
- **前置条件**: 用户已登录
- **主要流程**:
  1. 用户点击"创建目标"按钮
  2. 输入目标信息：
     - 目标标题（必填）
     - 目标描述（选填）
     - 目标标签（选填）（个人/工作/学习/健康等）。Tag可以手动输入，可以复用已经输入过的Tag
     - 目标截止日期（选填）
     - 目标优先级（高/中/低）
     - 成功标准/KPI（选填）
  3. 保存目标
  4. 系统存储目标并显示在目标列表中
- **后置条件**: 目标创建成功并显示在列表中

#### 1.1.2 修改目标
- **角色**: 已认证用户
- **前置条件**: 目标已存在且属于当前用户
- **主要流程**:
  1. 用户从目标列表选择要修改的目标
  2. 进入编辑界面
  3. 修改目标信息：
     - 可修改所有创建时的字段
     - 目标状态（进行中，暂停中，已完成）
  4. 保存修改
  5. 系统更新目标信息
- **后置条件**: 目标信息更新成功
- **异常流程**:
  - 如果目标已完成，需要确认是否重新激活
  - 如果修改影响关联计划，显示影响提示

#### 1.1.3 删除目标
- **角色**: 已认证用户
- **前置条件**: 目标已存在且属于当前用户
- **主要流程**:
  1. 用户选择要删除的目标
  2. 系统检查是否有关联的计划
  3. 如果有关联计划：
     - 提示用户有X个关联计划
     - 询问处理方式：
       - a. 同时删除所有关联计划
       - b. 取消删除操作
  4. 用户确认删除操作
  5. 系统执行删除（软删除或硬删除）
- **后置条件**: 目标及相关数据处理完成
- **异常流程**: 用户取消删除操作

#### 1.1.4 查看目标列表 (List)
- **角色**: 已认证用户
- **主要流程**:
  1. 用户进入目标页面
  2. 系统显示目标列表，支持：
     - 按状态筛选（进行中/已完成/暂停中）
     - 按优先级排序
     - 按截止日期排序
  3. 显示每个目标的概览信息：
     - 标题和进度条
     - 关联计划数量
     - 截止日期
- **后置条件**: 目标列表显示成功

### 1.2 计划管理

#### 1.2.1 创建计划
- **角色**: 已认证用户
- **前置条件**: 用户已登录，目标已存在
- **主要流程**:
  1. 用户选择创建计划的方式：
     - a. 从目标详情页创建（自动关联）
  2. 输入计划信息：
     - 计划名称（必填）
     - 计划描述（选填）
     - 关联目标（自动填充）
     - 开始日期（必填，默认今天）
     - 结束日期（必填，默认目标的截止日期）
     - 重复设置（一次性/每日/每周/每月/自定义）
       自定义可以设置n天重复一次，天是最小的单位
     - 任务配置（可选择以下组合）：
      - 时间：分钟单位，计时用
      - 次数：需要重复若干次才算完成的任务
      - 评价列表：用户可以输入一个列表，用来标识任务的结果，比如（好/中/差），或者（1/2/3/4/5）
      注：允许的组合：纯计时、纯计数、纯评价、计时+计数、计数+评价、无配置（简单任务）
          不允许的组合：计时+评价（互斥）
     - 完成条件（占位）
  3. 保存计划
  4. 系统创建计划并关联到目标（如果有）
- **后置条件**: 计划创建成功

#### 1.2.2 修改计划
- **角色**: 已认证用户
- **前置条件**: 计划已存在且属于当前用户
- **主要流程**:
  1. 用户选择要修改的计划
  2. 进入计划编辑界面
  3. 可修改的内容：
     - **计划名称不可修改**（创建时设定，作为计划的唯一标识）
     - 计划描述可修改
     - 时间范围（结束日期）可修改
     - 任务配置，可修改
     - 重复规则，可修改
  4. **不可修改的内容**：
     - 计划名称（immutable）
     - 开始日期（已开始执行的计划）
     - 关联目标（创建后不可更改）
  5. 保存修改
  6. 系统更新计划信息
  7. 如果修改影响到目标进度，重新计算目标完成度
- **后置条件**: 计划更新成功
- **业务规则**:
  - 已完成的计划修改需要确认
  - 修改时间范围需要验证合理性

#### 1.2.3 删除计划
- **角色**: 已认证用户
- **前置条件**: 计划已存在且属于当前用户
- **主要流程**:
  1. 用户选择要删除的计划
  2. 系统显示计划详情和影响：
     - 包含的任务数量
     - 完成进度
     - 关联的目标
  3. 用户选择删除方式：
     - 删除计划和所有任务
  4. 确认删除
  5. 系统执行删除操作
- **后置条件**: 计划删除成功

#### 1.2.4 查看计划列表 (List)
- **角色**: 已认证用户
- **主要流程**:
  1. 用户查看计划（可从目标详情或独立页面）
  2. 系统显示计划列表，支持：
     - 按时间范围筛选（今日/本周/本月）
     - 按状态筛选
     - 按关联目标分组
  3. 显示计划概览：
     - 计划名称和进度
     - 时间范围
     - 任务完成情况
- **后置条件**: 计划列表显示成功

## 2. 任务执行

### 2.1 任务更新

#### 2.1.1 生成任务
- **角色**: 系统自动/已认证用户触发
- **前置条件**:
  - Plan已存在且处于活跃状态
  - 达到生成条件（刷新Task页面）
  - 该Plan对应的最后一个Task的执行时间窗口在当前时间之前
- **主要流程**:
  1. 系统检查Plan的重复规则和时间设置
  2. 验证生成条件：
     - 检查是否到达计划开始时间
     - 计划对应的最后一个task的执行时间窗口在今天之前
  3. 生成Task实例：
     - 分配唯一Task ID
     - 继承Plan的基本信息（名称、描述、类型）
     - 设置执行时间窗口
       根据上一个task来决定时间窗口，开始时间应该和上个task的截止时间相同（不是完成时间），截止时间根据重复时间计算。
     - 初始状态设为Active
     - 关联到源Plan
  4. 根据Task类型初始化任务配置：
  5. 将Task加入“当前时间窗口队列”
- **后置条件**: Task成功生成并处于待执行状态
- **异常流程**:
  - 如果Plan里最后Task的执行时间窗口包含当前时间，跳过
- **业务规则**:
  - 同一Plan的Task按时间顺序排列

#### 2.1.2 自动刷新任务
- **角色**: 系统自动
- **前置条件**: 系统正在运行
- **主要流程**:
  1. 定时检查需要生成的Task
     - 每日凌晨批量生成
     - 打开Task页面时生成
  2. 更新Task状态：
     - 检查超时的Task，如果状态不是Complete，则把状态更新成Skipped，移出“当前时间窗口队列”

- **后置条件**: 任务列表更新完成

### 2.2 显示任务列表

#### 2.2.1 查看Task队列
- **角色**: 已认证用户
- **主要流程**:
  1. 用户进入Task队列页面
  2. 系统显示Task列表：
     - 按时间排序的待执行Task
     - 当前进行中的Task（高亮显示）
     - 最近完成的Task
  3. 支持的查看模式：
     - 今日视图: 仅显示今日的Task
     - 总视图: 所有“当前时间窗口队列”中的Task，按重复周期分类显示
  4. 显示Task信息：
     - Task名称和类型图标
     - 预计执行时间/时长
     - 需要重复次数
  5. 提供快速操作：
     - 开始计时
     - 确认完成
     - 标记结果
- **后置条件**: Task队列显示完成



### 2.3 执行任务

#### 2.3.1 开始计时
- **角色**: 已认证用户
- **前置条件**:
  - Task存在且状态为Active
  - 只针对任务配置中设置了时间的情况
- **主要流程**:
  1. 用户选择要执行的计时类Task
  2. 系统验证执行条件
  3. 启动计时器：
     - 显示倒计时或正计时
  4. 提供控制选项：
     - 完成
     - 取消
- **后置条件**: Task进入计时执行状态

#### 2.3.2 直接完成
- **角色**: 已认证用户
- **前置条件**:
  - Task存在且状态为Active
  - 只针对任务配置中没有配置时间和结果列表的情况
- **主要流程**:
  1. 用户选择直接完成Task
  2. 完成次数加1
  3. 如果有重复次数配置：
     - 如果完成次数仍小于重复次数，记录完成次数，退出流程。
  4. 记录完成信息：
     - 完成时间
     - 完成数据
     - 执行备注（可选）
  5. 更新Task状态为Completed
  6. 更新关联的Plan进度
- **后置条件**: Task完成，数据已保存
- **业务规则**: 完成的Task不可撤销

#### 2.3.3 选择评价并完成
- **角色**: 已认证用户
- **前置条件**:
  - Task存在且状态为Active
  - 只针对配置里有结果列表的情况
- **主要流程**:
  1. 用户选择Task
  2. 系统显示评价表单：
     - 加载评价维度
     - 显示评分选项
  3. 用户填写评价：
     - 选择评分等级
     - 填写评价说明（可选）
     - 添加改进建议（可选）
  4. 提交评价：
     - 验证评价完整性
     - 保存评价数据
  5. 更新Task状态为Completed
  6. 计算并更新相关统计
- **后置条件**: Task完成，评价已记录

#### 2.3.4 执行已完成任务
- **角色**: 已认证用户
- **前置条件**:
  - Task存在且状态为Complete
  - Task的执行时间窗口包含了当前时间
- **主要流程**:
  1. 用户选择Task
  2. 用户仍然使用2.3.1或者2.3.2或者2.3.3的方式执行任务
  3. 自动创建一个新的Task，除了Id，其他内容和选中task一样，完成次数重置成0
  4. 执行2.3.1或者2.3.2或者2.3.3的流程

## 3. 结果回顾

### 3.1 显示所有Plan的列表

#### 3.1.1 Plan总览
- **角色**: 已认证用户
- **主要流程**:
  1. 用户进入结果回顾页面
  2. 系统显示所有Plan的概览：
     - Plan名称和描述
     - 关联的Goal
     - 创建时间和时间范围
     - 总体完成率
     - Task统计（总数/完成/跳过）
  3. 支持筛选和排序：
     - 按Goal筛选
     - 按时间范围筛选
     - 按完成率排序

- **后置条件**: Plan列表展示完成

### 3.2 显示单个Plan的详细执行History

#### 3.2.1 Plan执行历史详情
- **角色**: 已认证用户
- **前置条件**: Plan已存在且有执行记录
- **主要流程**:
  1. 用户选择要查看的Plan
  2. 系统加载该Plan的所有Task历史：
     - 执行时间线
     - 每个Task的详细信息
     - 执行状态分布
  3. 显示统计分析：
     - 完成率趋势图
     - 平均执行时长
     - 最佳执行时段
     - 跳过原因分析
  4. 显示详细记录：
     - 每个Task的执行时间
     - 实际完成数据
     - 评价得分（如果有）
     - 执行备注
  5. 提供数据操作：
     - 时间范围筛选
     - 导出历史数据
     - 生成分析报告
- **后置条件**: 历史详情展示完成

#### 3.2.2 Task执行历史
- **角色**: 已认证用户
- **主要流程**:
  1. 用户进入历史记录页面
  2. 选择时间范围：
     - 最近7天
     - 最近30天
     - 自定义日期范围
  3. 系统加载历史Task：
     - 已完成的Task
     - 已跳过的Task
     - 执行数据统计
  4. 显示历史详情：
     - 执行时间和时长
     - 完成度/完成数量
     - 评价得分（如果有）
     - 执行备注
  5. 提供统计视图：
     - 完成率趋势图
     - 平均执行时长
     - 类型分布图
     - Plan完成情况
  6. 支持数据导出：
     - 导出为CSV
     - 生成报告PDF
- **后置条件**: 历史记录查询完成

#### 3.2.3 生成执行报告
- **角色**: 已认证用户
- **主要流程**:
  1. 用户选择报告参数：
     - 时间范围
     - 包含的Plan/Goal
     - 报告类型（简要/详细）
  2. 系统收集数据：
     - Task执行记录
     - 完成率统计
     - 时间分布
     - 跳过原因分析
  3. 生成报告内容：
     - 执行概览
     - 各Plan完成情况
     - 时间效率分析
     - 改进建议
  4. 提供可视化：
     - 完成趋势图
     - 时间分配饼图
     - 效率对比图
  5. 支持分享功能：
     - 生成分享链接
     - 导出为图片
     - 发送到邮箱
- **后置条件**: 报告生成完成

## 5. 用户管理

### 5.1 用户注册
- **角色**: 未认证用户
- **前置条件**: 用户未注册
- **主要流程**:
  1. 用户进入注册页面
  2. 填写注册信息：
     - 用户名（唯一）
     - 邮箱地址
     - 密码（需要确认）
     - 同意用户协议
  3. 提交注册信息
  4. 系统验证信息：
     - 用户名唯一性
     - 邮箱格式
     - 密码强度
  5. 发送验证邮件（可选）
  6. 创建用户账户
  7. 自动登录或跳转登录页
- **后置条件**: 用户账户创建成功
- **异常流程**:
  - 用户名已存在
  - 邮箱已被注册
  - 密码不符合要求

### 5.2 用户登录
- **角色**: 未认证用户
- **前置条件**: 用户已注册
- **主要流程**:
  1. 用户进入登录页面
  2. 输入登录凭据：
     - 用户名/邮箱
     - 密码
  3. 提交登录请求
  4. 系统验证凭据
  5. 创建用户会话
  6. 跳转到主页面
- **后置条件**: 用户登录成功，会话创建
- **异常流程**:
  - 用户名/密码错误
  - 账户被锁定
  - 需要二次验证

### 5.3 退出登录
- **角色**: 已认证用户
- **前置条件**: 用户已登录
- **主要流程**:
  1. 用户点击退出登录
  2. 系统确认退出（可选）
  3. 清除用户会话
  4. 清除本地缓存（可选）
  5. 跳转到登录页面
- **后置条件**: 用户会话结束

### 5.4 修改密码
- **角色**: 已认证用户
- **前置条件**: 用户已登录
- **主要流程**:
  1. 用户进入账户设置
  2. 选择修改密码
  3. 输入密码信息：
     - 当前密码
     - 新密码
     - 确认新密码
  4. 系统验证：
     - 当前密码正确性
     - 新密码强度
     - 两次输入一致
  5. 更新密码
  6. 发送通知邮件（可选）
- **后置条件**: 密码修改成功
- **异常流程**: 当前密码错误

### 5.5 用户注销
- **角色**: 已认证用户
- **前置条件**: 用户已登录
- **主要流程**:
  1. 用户进入账户设置
  2. 选择注销账户
  3. 系统显示注销影响：
     - 数据将被删除
     - 无法恢复
  4. 要求二次确认：
     - 输入密码
     - 输入注销原因（可选）
  5. 执行注销：
     - 标记账户为已注销
     - 清理或归档数据
     - 结束所有会话
  6. 跳转到首页
- **后置条件**: 账户注销成功
- **业务规则**: 可设置冷静期，期间可恢复

## 业务规则总结

### Goal相关规则
1. **目标创建规则**: 必须包含标题，其他信息可选
2. **目标删除规则**: 有关联计划时需要选择处理方式

### Plan相关规则
1. **计划创建规则**: 必须设置名称、开始日期、结束日期
2. **计划修改规则**:
   - 计划名称可修改，但需保持在用户范围内唯一
   - 修改名称不会影响已生成的任务
3. **计划删除规则**: 计划删除了，任务都会被一起删除

### Task相关规则
1. **Task生成规则**:
   - Task只能由Plan自动生成
   - Task的执行时间窗口（开始时间，截止时间）在Plan确定的时候就被确定了
   - 自动生成时机由最后Task的执行时间窗口和当前时间决定
   - 每个执行时间窗口内可能有多个Task，用户可以重复已完成的Task，重复完成的Task应该进入History，可以进行回顾。

2. **状态转换规则**:
   - Active → Completed/Skipped
   - 状态转换不可逆

3. **并发控制规则**:
   - 每个Plan同时只能有至多一个Active的Task
   - 使用执行锁机制保证唯一性

4. **数据保存规则**:
   - Task永不物理删除
   - 所有状态变更都要记录时间戳
   - 执行数据作为历史永久保存

5. **优先级规则**:
   - Task继承Plan的优先级
   - 时间冲突时，高优先级优先
   - 用户可手动调整执行顺序
